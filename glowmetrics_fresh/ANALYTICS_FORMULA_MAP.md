# CamCash — Analytics Formula & Surface Map

Every metric, formula and insight the product calculates, what it is made of,
and exactly where (or whether) a creator ever sees it.

Generated by reading the code, not the docs. Source of truth for each entry is
the file/function named in its row.

Legend for **Surfaced**:

- **✅ Shown** — rendered to the creator, location given.
- **🟡 Internal** — computed and consumed by another calculation, never rendered.
- **❌ Not surfaced** — computed and returned, but nothing renders it (dead output).

---

## 1. Architecture — the four layers

```
RAW DATA            tips / live_tips / paid_sessions (Supabase)
   ↓
LAYER A  CANONICAL  lib/analytics.js  +  lib/analytics/*  +  lib/coaching/triggers.js
   ↓                (all pure functions; the only place a formula is defined)
LAYER B  SERVICE    app/api/insights/*  (server-side orchestration)
LAYER C  ENTITLEMENT lib/entitlement.js redact()  → Free = preview, Pro = data
   ↓
UI                  app/dashboard/* components (render only, compute nothing)
```

A second, **parallel** engine exists in SQL: the `get_user_insights` RPC
(Postgres). It independently computes best-hour, missed opportunity, momentum
and a 5-rule insight feed. It is *not* consolidated with Layer A — see §8.

**Timezone contract:** every local-time bucket uses the creator's resolved
`profiles.timezone` (`lib/timezone.js` → `resolveCreatorTimezone`), routed through
`lib/analytics/localTime.js` (`toLocalHour` / `toLocalDow` / `toLocalDateStr`).
Never the browser zone, never raw UTC.

## 2. Constants (`lib/constants.js`)

| Constant | Value | Used for |
|---|---|---|
| `PLATFORM_TOKEN_RATES` | CB 0.05, Bonga 0.025, MFC 0.05, Stripchat 0.05, CamSoda 0.05 | model payout per token; `tokenRate(platform)`, default 0.05 |
| `PLATFORM_VIEWER_RATES` | CB 0.10, Bonga 0.0682253, MFC 0.0908909, Stripchat 0.0925741, CamSoda 0.1099 | what a viewer *paid* per token; default 0.10 |
| `WHALE_LIFETIME_TOKEN_THRESHOLD` | 500 | absolute "whale" label (Money Map, Stream Planner) |
| `UNDETECTED_PLATFORM` | `'Unknown'` | CSV parser bucket; excluded from every "best platform" ranking |

Two deliberately different "whale" definitions coexist:

- **Absolute** — ≥500 lifetime tokens (Money Map stat, Stream Planner roster).
- **Relative** — percentile tiers inside the creator's own base (`identifyWhales`).

## 3. Core account analytics — `aggregateRows(tips, tz)` (`lib/analytics.js`)

One call produces the whole dashboard payload. Everything below is a key of its
return value.

### 3.1 Totals

| Metric | Formula | Surfaced |
|---|---|---|
| `totalUSD` | Σ tip.usd | ✅ Command Center, Creator Report, Performance, KPI cards |
| `totalTokens` | Σ tip.tokens | ✅ Money Map / token surfaces |
| `totalTips` | tips.length | ✅ Overview / Report counts |
| `avgTipSize` | totalUSD / tips.length | ✅ Money Map, platform cards |
| `uniqueFanCount` | count of distinct usernames (= `identifyWhales().length`) | ✅ Command Center, Fans, Performance |

### 3.2 Sessions (`lib/analytics/sessions.js`)

Sessions are **inferred**, never recorded: CSVs carry tip timestamps only.

- **Grouping (`detectSessions`)** — new session when the platform changes OR the
  gap since the last tip exceeds **3 h**. Start/end = first/last tip timestamp.
- **Duration** — `endTime − startTime`; `durationUnknown = true` when it rounds
  to 0 min (single-tip session).
- **Quality (`classifySession`)**
  - `invalid` — <2 min **and** $0
  - `low_signal` — <15 min **and** <$10
  - `meaningful` — everything else ← the population every rate/best-time calc uses
- **`sessionWeight`** = `0.4·min(mins/120,1) + 0.6·min(usd/100,1)` → 🟡 internal, never rendered.
- **Per-session derived:** `usdPerHour`, `tokensPerHour`, `usdPerMinute`,
  `avgTipSize`, `uniqueFans`, `topContributor` + `topContributorPct`,
  `velocityTrend` (2nd-half $/min vs 1st-half: >1.15× `growing`, <0.75× `dying`,
  else `steady`; only when ≥10 min).

| Metric | Formula | Surfaced |
|---|---|---|
| `meaningfulSessionCount` | count of meaningful | ✅ Command Center, Performance, Report |
| `lowSignalSessionCount` | validCount − meaningfulCount | ✅ Performance reliability card |
| `totalStreamMinutes` | Σ hours of timed meaningful sessions × 60 | ✅ Command Center, Performance |
| `sessions` / `allValidSessions` / `meaningfulSessions` | populations | ✅ Sessions tab, Analytics tab |

### 3.3 Estimated $/hour

```
eligible session := tipCount ≥ 2 AND known duration AND ≥15 min AND usd > 0
estimatedHourlyRate = Σ eligible usd / (Σ eligible minutes / 60)     ← weighted, never mean-of-rates
```

| Field | Surfaced |
|---|---|
| `estimatedHourlyRate` | ✅ Command Center, Performance, Creator Report, Stream Planner, sticky command bar |
| `hourlyRateSessionCount`, `hourlyRateTotalMinutes` | ✅ as the "based on N sessions / Xh tracked" subtext |
| `hourlyRateTotalUsd` | 🟡 internal |
| `excludedUntimedSessionCount` | ❌ **not surfaced** — computed, zero readers |

Display gate: `canShowHourlyRate` — ≥3 eligible sessions **and** ≥60 tracked minutes.

`earningsVelocity` (legacy $/h over *all* timed meaningful sessions, looser rule
than the above) — ❌ **not surfaced**: assigned in `page.js:2489` and never read.

### 3.4 Best times — the canonical engine (`lib/analytics/bestTimes.js`)

`computeCanonicalBestTimes(meaningfulSessions, tz)`:

- Unit of analysis: **sessions**, bucketed by (local day × local hour of start).
- Statistic: **median session $/hour** per bucket (never a mean, never total $).
- Confidence tiers by session count in the bucket:
  | sessions | tier | may be called "Best Time"? |
  |---|---|---|
  | <2 | `insufficient` | never shown |
  | 2–3 | `promising` | shown only as "Early signal" |
  | 4–5 | `supported` | yes (medium) |
  | 6+ | `high` | yes (high) |
- `bestWindow` = highest median $/hr among supported/high; ties → more sessions →
  more recently active.
- `earlySignal` = strongest `promising` bucket, only when no `bestWindow` exists.
- `newTipperRate` = share of the bucket's tips that were a tipper's first ever.
  Deliberately **excluded** from the ranking; used by Stream Planner's Growth Mode.

| Output | Surfaced |
|---|---|
| `canonicalBestTimes.bestWindow` | ✅ Command Center hero, Creator Report "Best Streaming Time", Performance, Stream Planner grid, Fans |
| `canonicalBestTimes.grid` (all buckets + tiers) | ✅ Stream Planner week grid / Performance |
| `canonicalBestTimes.earlySignal` | ✅ Stream Planner ("Early signal" badge) |
| `newTipperRate` | ✅ Stream Planner Growth Mode ranking only |
| `platforms[].bestLocalDay / bestLocalHour / bestWindowConfidence` | ✅ Platform ROI card "Best window" badge |

**Legacy best-time path, still computed:** `computeBestTimes(tips, tz)` — the
*tip-level* median-per-hour/day version producing `bestDay`, `worstDay`,
`bestHour`, `earlySignalHour`.

| Field | Surfaced |
|---|---|
| `bestDay` / `bestHour` | 🟡 internal only — they still feed `generateInsights()` and `generateLossAlerts()`; assigned in `page.js` as `analyticsbestDay`/`analyticsBestHour` and **never rendered** |
| `earlySignalHour` | ❌ **not surfaced** — zero readers anywhere |
| `platformBestTimes` (per-platform hour/day/day×hour grids, mean of medians, 3-bucket floor) | 🟡 internal — only consumed by `buildRealTimeAlerts()`; the Platforms-tab heatmap that rendered it was removed |

> Unit warning documented in the code: `bestDay.avg` is **median dollars per day
> streamed**, while `bestWindow.medianUsdPerHour` is **median $/hour**. They are
> not comparable and previously read as a contradiction on screen.

### 3.5 Missed revenue (`lib/analytics/missedRevenue.js`)

```
rateGapUsdPerHour = platform's best-window median $/hr − platform's overall median $/hr
```

Gating: platform has ≥3 meaningful sessions, window beats overall median by
>1.2×, and gap ≥ $1/hr.

Also returned: `bestLocalDay/Hour`, `bestWindowMedianUsdPerHour`,
`overallMedianUsdPerHour`, `sessionsNotAtBestWindow`, `offWindowHours`.

**No cumulative dollar total is produced, deliberately** — gap × off-window hours
implies a counterfactual the data can't support (91% of lifetime earnings on the
regression fixture). Ranking uses the rate gap directly.

| Field | Formula | Surfaced |
|---|---|---|
| `today_missed` | best window's hour already passed locally today and no session hit it → loss = window median $/hr, capped at $200 | ✅ Command Center / Performance |
| `cumulative_by_platform` | per above | ✅ Performance "You're losing money" |
| `recent_streak_missed` | best window not hit in the last 3 days → window median $/hr × 3 | ✅ Command Center / Performance |

### 3.6 Fan intelligence — `identifyWhales(tips, tz)`

Per fan: `totalUSD`, `totalTokens`, `tipCount`, `avgTipSize`, `biggestTip`,
`firstTipDate`, `lastTipDate`, `daysSinceLastTip`,
`avgDaysBetweenTips = lifetimeDays / (tipCount−1)` (30 when a single tip),
`privateCount` / `privateSpent`, `tipNotes`.

**Tiers** (percentile rank by lifetime USD *within this creator's base*):

| rank | tier |
|---|---|
| top 5% | 🐳 Whale |
| top 20% | 🦈 Shark |
| `daysSinceLastTip > max(60, avgGap×3)` | 💤 Dormant |
| else | 🐟 Regular |

| Derived metric | Formula | Surfaced |
|---|---|---|
| `tipProbability` | days-since / avg-gap ratio → High 85% (<0.5×) / Medium-High 70% (<1×) / Medium 50% (<1.5×) / Low-Medium 30% (<2×) / Low 15% | ✅ Fans tab, fan intelligence panel |
| `churnRisk` | ratio <1 Low·Active, <2 Medium·Watch, <3 High·At risk, else Critical·Likely churned; `Unknown` under 3 tips | ✅ Fans tab |
| `lifetimeValue` | `(spent/lifetimeDays)×365`, monthly = /12; confidence High >10 tips, Medium >5, else Low. Under 7 days or 2 tips → per-day×30, Low | ✅ Fan intelligence panel |
| `expectedNextTip` | `round(avgGap − daysSince)` → Overdue / Tomorrow / In N days / In ~N weeks | ✅ Fans tab |
| `typicalOnlineHours` / `peakLocalHour` / `peakHourTipCount` | modal creator-local tip hour, rendered as "8 PM – 10 PM" | ✅ Fans tab ("usually around now") |
| `spendPercentile`, `isTopSpender` | `(1 − percentileRank)×100`; top 5% | ✅ Fans tab badges |
| `topTippers` (ranked view of the same data) | rank + emoji status | ✅ Creator Report top supporter |

Display gate: `canShowWhales` — ≥5 unique fans **and** ≥$50 lifetime.
Free tier sees `FREE_FAN_LIMIT` fans; the rest are blurred.

### 3.7 Concentration & retention

### 3.9 Monthly & momentum

`monthlyData[]` — creator-local calendar month (never UTC):
`usd`, `tips`, `fans`, `sessions` (meaningful only), `usdPerFan`,
`hours` + `usdPerHour` (built from the *same* hourly-rate-eligible population),
`growthPct`, `prevMonth`, `gapMonths` (months of zero activity skipped — so a
huge growthPct after a gap can be shown with context), plus
`usdPerHourGrowthPct`, `hoursGrowthPct`, `sessionsGrowthPct`, `fansGrowthPct`.

| Metric | Surfaced |
|---|---|
| `monthlyData` | ✅ Monthly tab, Performance "What changed?", Dashboard growth charts |
| `bestMonth` | ✅ Monthly tab |
| `momentum` | ✅ Command Center + Performance |

`momentum` = last-30-days USD vs prior-30: `Surging` >50% (also when prior=0),
`Growing` >10%, `Steady` >−10%, `Declining` otherwise; `Inactive` (−100%) when
last-30 is zero, `No data` when both are zero. Zero revenue is explicitly *not*
reported as a measured decline.

> Note: `momentum` filters on `t.date_time` while the rest of `aggregateRows`
> prefers `t.dateRaw || t.date_time`.

### 3.10 Session performance distribution

Median split of the hourly-rate-eligible population (needs ≥4 such sessions):
`medianUsdPerHour`, `aboveMedian {count, avgUsdPerHour}`,
`belowOrAtMedian {…}`, plus `avgMeaningfulSessionUSD` and
`avgMeaningfulSessionMinutes`.
✅ Performance; gate `canShowSessionPerf` (≥3 sessions).

### 3.12 Generated insight/alert feeds

All four are **still computed on every load**; only `nextMoves` reaches a screen.

**`generateInsights()`** — priority-sorted, then filtered by `validateInsights()`
(drops anything containing "$0" or a "100% returning" claim):

| Insight | Trigger |
|---|---|
| 📅 Best vs worst day | both exist, differ, bestDay.avg > 0 → multiplier + cost of missing |
| ⏰ Peak hour | `bestHour` exists → hour avg vs overall session avg multiplier |
| 🐳 Top-fan share | top Whales (or Sharks) → % of revenue, avg loss per fan |
| ⏱️ Long vs short streams | ≥3 sessions each side of 60 min and long ≥1.2× short → % more + $/30 min |
| 🔁 Retention | >10 fans → returning %, returning-vs-new spend multiplier |
| 📈/📉 Weekly momentum | this-week vs last-week revenue, \|change\| ≥10% |

**Surfaced:** ✅ Creator Report only (it picks one 📉 "warning" and one other as
"opportunity"). ❌ The Overview "Smart Insights" block that rendered the full list
was **deleted** — `page.js` still assigns `insights` and never renders it.

**`generateWhaleAlerts(whales)`** — `new_whale` (Whale tier, tipped <7 d, top
spender), `churn_risk` (High/Critical risk, spend ≥ 50% of avg whale spend, ≥3
tips), `tip_likely` (High probability, spend ≥ 80% of avg), `returned` (tipped
within 3 d after a gap >1.5× their average, >5 tips). Filtered to relevant fans
(≤90 d dormant, ≥100 tokens), sorted critical→success.
❌ **Not surfaced** — assigned at `page.js:2453`, never rendered.

**`generateLossAlerts()`** — `peak_missed` (no session within ±1 h of the peak
hour in 3 days → loss = bestHour.avg × 3), `tip_drop` (avg tip down ≥15% week over
week), `fan_churn` (top 2 fans ≥$50 lifetime, dormant 5–30 d), `streak_broken`
(no stream >2 days with >5 sessions of history).
❌ **Not surfaced** — assigned at `page.js:2454`, never rendered.

**`generateNextMoves()`** — go-live-now/soon/plan by hours until peak; tonight's
goal (`expected × 1.2`); up to 3 "message this fan" CTAs (dormant 3–45 d, ≥$20
lifetime, recovery estimate = `avgTipSize × 2`); a session goal
(`avg × 1.2` rounded to $5) with a hit count. Top 5 by priority.
✅ Command Center "Do this now" (merged with real-time alerts + the SQL go-live
signal, capped at 3) and Creator Report.

**`predictRevenue()`** — `next7Days` / `next30Days` (trailing sums with
confidence bands and a 30-vs-prior-30 trend) and `tonightStream` (same weekday's
sessions, ≥3 required: expected = mean, range = p10–p90 clamped so max ≤ 3× min,
`returningTippers` = mean unique fans × 0.4).
🟡 Only `tonightStream` reaches a screen, indirectly, through `generateNextMoves`'s
goal line. `next7Days`/`next30Days` are ❌ not surfaced.

### 3.13 Real-time alerts (in `page.js`, not the library)

`buildRealTimeAlerts()` — recomputed every 60 s from tips + whales +
`platformBestTimes`. ✅ Merged into the Command Center's action list (top 3).

### 3.14 Per-session breakdown engine (Sessions tab, `page.js`)

Computed per session on expand: 5-minute revenue buckets, peak bucket/minute,
first-half vs second-half split, top tippers with %, spike detection
(bucket > 2× the session's average bucket), performance band vs the account
average (≥1.3× strong, ≤0.7× weak), revenue per minute, plus rule-based
`insights[]` and `recommendations[]`. ✅ Sessions tab.

## 4. Live Mode (real-time) — `lib/analytics/*` + `lib/coaching/triggers.js`

Session state (`computeCoachingState` server-side / `computeState` client-side):
`totalRevenue`, `totalTokens`, `elapsedMins`, `timeSinceLastTip`,
`goalProgress = min(100, tokens/goalTokens)`, `paceStatus`
(2nd-half $/min vs 1st: >1.15× `above`, <0.75× `below`, else `on_track`; needs ≥3
tips and ≥5 min), `paceDeltaPct`, `liveOnlyCount`, `topTipper`.

| Metric | Formula | Surfaced |
|---|---|---|
| **Room health** (`roomHealth.js`) | 0–100: tip recency ≤40 + tip rate ≤30 + pace ≤20 + event density ≤10. States: Explosive ≥80, Hot ≥62, Active ≥44, Warming ≥22, else Cold. Direction: Spiking / Rising / Falling / Stable | ✅ Live Mode hero + strip |
| `roomHealth.confidence` | `(liveOnlyCount/5)×60 + (elapsedMins/20)×40` | 🟡 **internal only, by rule** — never rendered as a %; the UI shows "N tips · M min" instead |
| **Session phase** (`sessionPhase.js`) | STARTUP (<5 min or <2 tips) → PEAK (above pace, ≥25 min, ≥8 tips) → GROWTH → DECLINE (>10 min dry, or below pace ≥20 min) → RECOVERY (was declining, tips resumed) → PLATEAU (on track ≥10 min) | ✅ Live Mode phase badge |
| `getRecoveryActions(phase)` | fixed action list per phase | ✅ Live Mode |
| `getGoalStrategy()` | `timing` / `urgency` / `suggestion` from real `goalProgress` + `paceStatus` | ✅ Live Mode goal card |
| `getGoalStrategy().probability` | hardcoded 100/85/72/25/50 — **not** a computed likelihood | 🟡 **internal only, by rule** — deliberately no longer rendered |
| **Opportunity score** (`opportunity.js`) | 0–100: heat ≤30 + pace ≤25 + goal proximity ≤20 + tip recency ≤15 + tip rate ≤10. Labels: Peak conversion ≥80, Strong ≥60, Moderate ≥40, Building ≥20, Low | ✅ Live Mode score + signal list |
| **Stream health** (`opportunity.js`) | momentum ≤30 + engagement (heat×0.3) ≤30 + velocity (recency) ≤25 + recovery (phase) ≤15 → grade A ≥85 / B ≥70 / C ≥55 / D ≥40 / F | ✅ Live Mode grade + 4 component bars |
| **Revenue velocity** (`velocity.js`) | current $/min vs mean and max of historical sessions (≥15 min, >$0): `pctVsAvg`, `pctVsBest`, trend band ±10/±30% | ✅ Live Mode Rev/hr tile |
| **Live comparison** (`velocity.js`) | current $/h vs avg / best / last session | ✅ "vs Avg" tile; `vsBestPct` and `vsLastPct` computed but ❌ not rendered |

### Coaching triggers (`lib/coaching/triggers.js`) — 9 rules, one fires

Priority order, then fixed rule order as tie-break; each has its own cooldown:

| Trigger | Condition | Cooldown |
|---|---|---|
| `dead_air_critical` (P1) | no tip ≥8 min (6 if strategy aggressive) | 3 min |
| `goal_push` (P1) | goal 90–99% (80% if aggressive/goal) | 4 min |
| `dead_air_high` (P2) | no tip ≥5 min (4 aggressive), below critical | 5 min |
| `pace_below` (P2) | pace below, ≥8 min, ≥3 tips | 5 min |
| `stream_fatigue` (P2) | >75 min, pace below, ≥5 tips | 15 min |
| `pace_above` (P3) | pace above, ≥8 min, ≥3 tips | 8 min |
| `goal_hit` (P3) | goal ≥100% | 10 min |
| `whale_prox` (P3) | a tipper's gap ≥1.3× their own average (avg gap <15 min, ≥2 min since) | 6 min |
| `whale_dep` (P4) | top tipper ≥45% of session revenue | 10 min |

`confidence` per trigger is a derived 0–1 ratio (e.g. `timeSinceLastTip / (threshold×2)`).
✅ The single selected trigger renders in Live Mode and in the Chrome extension
(both call the same route → same module). Non-selected triggers are discarded,
never queued.

## 6. Tools tabs with their own calculations

**Money Map** (`MoneyMap.js`) — uses canonical `detectSessions` but its own
aggregations: 7×(2-hour) heatmap grid of tokens/USD, `platformEfficiency`
(avgTip, `usdPerDay` over active days), `detectWhales` (absolute ≥500 tokens),
`monthlyTotals` (last 12), `weeklyEfficiency` ($/hr per bucket, last 12),
`earningsBySource`. ✅ Money Map tab (heatmap free; Sessions/Platforms/Trends
sub-tabs Pro). Needs ≥20 tips.

> Its `weeklyEfficiency` buckets by `YYYY-MM` despite the "week" naming — it is
> effectively a monthly $/hr series.

**Stream Planner** (`StreamPlanner.js`) — reads canonical `bestTimes` grid and
`estimatedHourlyRate`, plus its own: `untestedWindows` (never-streamed slots),
`detectWhales` (absolute ≥500 tokens, with each fan's modal local day/hour),
`multiStreamAnalysis` (avg $/hr for 1 vs 2 vs 3+ platform sessions),
`planMatchScore` (% of tips inside recommended windows, ±1 h). ✅ Planner tab.

**Analytics tab** (`AnalyticsCharts.js`) — scatter of duration/tips/fans →
revenue, revenue distribution histogram with median + p75, outlier detection,
period comparison (sessions, avg $/h, avg session value, avg duration), and a
session reliability card. ✅ Analytics tab.

**Growth charts** (`DashboardGrowthCharts.js`) — tokens vs stream hours by
day / week / month / hour-of-day, plus the canonical monthly USD series.
✅ inside Performance.

## 7. Free vs Pro

- `lib/entitlement.js` `redact()` — Free gets `{unlocked:false, preview:{category,
  summary, count}}`; the `data` key is omitted entirely, not nulled.
- Data-readiness gates (`planLimits.js` / `DashboardPreview.js`):
  `canShowBestHours` (≥25 tips, ≥3 sessions), `canShowWhales` (≥5 fans, ≥$50),
  `canShowPlatformComp` (≥2 platforms, ≥4 sessions), `canShowSessionPerf`
  (≥3 sessions), `canShowRetention` (≥10 fans, ≥7 days), `canShowHourlyRate`
  (≥3 eligible sessions, ≥60 min).
- Free limits: 3 platforms, 31 days of history, `FREE_FAN_LIMIT` fans.
- Live Mode is Pro-only and is shown as locked *before* a session starts.

## 8. The SQL engine — `get_user_insights(p_user_id, p_timezone)`
